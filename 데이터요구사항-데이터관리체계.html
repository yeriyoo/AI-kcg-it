DAR-13 구조 관리 도구

관리 도구 체계 — 모델이 정본, DDL은 파생

단계 도구 · 산출물 정본 여부 산출 규칙
개념 · 논리 모델 ER 모델링 도구(ERwin / DA#) 정본 주제영역 → 개념 → 논리 3단계. 표준단어 · 도메인 적용 후 확정
물리 모델 AIFS_SB_08 데이터베이스설계서 · SB_09 전체ERD 정본 논리 모델에서 파생. 설계 범위 222 테이블 · 3,428 컬럼 (계획 테이블 포함 → 운영 DB와 범위가 다름)
DDL 반영 Flyway 마이그레이션 (V001~) 파생 물리 모델 확정 후 작성. 운영 DB 직접 DDL 금지
운영 DB PostgreSQL kcgaidb (스키마 kcg) 파생 마이그레이션으로만 변경. 수기 변경 시 형상 불일치로 검출

단일 방향 원칙 — 변경은 항상 「모델 → 설계서 → 마이그레이션 → 운영 DB」 순서로만 흐른다. 운영 DB에서 역방향으로 모델을 갱신 (리버스 엔지니어링)하는 경로는 형상 관리를 무력화하므로 사용하지 않는다.

항목 내용
점검 주기 월 1회 정기 + 마이그레이션 릴리즈 시마다 수시

최근 실적(운영 DB) 2026-10-04 표준화 재점검 — 운영 DB 131 테이블 · 1,915 컬럼(Flyway V127, 2026-10-01). 설계서 222 테이블은 계획 테이블을 포함한 설계 범위라 운영 DB와 범위가 달라 단순 건수 비교 대상이 아니다.

설계서 SB_08의 222 테이블 · 3,428 컬럼은 계획 테이블을 포함한 설계 범위이고, 위 수치는 현재 운영 DB다. 두 값의 차이는 불일치가 아니라 범위 차이이며, 전수 대조는 설계서↔ERD 및 운영 DB↔마이그레이션을 따로 수행한다.

형상 Git 커밋 (마이그레이션 SQL + 설계서) 누가 · 왜 바꿨는지, MR 리뷰로 승인 경로 확보
문서 설계서 개정이력 표 업무적 변경 사유 · 영향 범위 · 승인자

재반 충돌 방지 — 마이그레이션 번호는 선정 방식이라 브랜치 병행 작업 시 충돌한다. 운영 반영 전 스크래치 DB에서 검증하고, 재반은 기존 로그의 Current version 기준으로 확정한다.
