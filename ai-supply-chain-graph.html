공개데이터만으로는 어선→운반선→항만까지는 상당 부분 구성할 수 있으나, 항만→특정 가공업체→특정 수산시장을 확정적으로 연결하기는 어렵다. 이 구간은 Panjiva 같은 선적자료, 중국 기업정보, 냉동창고·시장 위치 및 가격 변화를 결합해 확률 관계로 구성해야 한다. 각 공개 통계가 시장·지역·HS코드 단위로 제공되고, Panjiva가 기업·선적 단위 관계를 제공한다는 점에 근거한 판단이다.

· 중점 농산물시장 정보 플랫폼(pfsc.agri.cn)은 인증 없이 응답하는 공개 API를 제공한다. 공개 API 확인 및 실제 연동 가능 여부는 별도 검증이 필요하다.

· 수집 전에는 각 데이터 제공기관의 이용약관, 접근 권한, 라이선스 및 재배포 조건을 확인해야 한다.

· 농업농촌부 데이터 포털(data.moa.gov.cn)은 농산물 도매가격·수산물 가격지수·주간 가격 동향·월별 수급 분석을 제공한다.

· Global Fishing Watch의 Events API는 선박 신원·조업·조우·체류·항만 방문 데이터를 제공하므로 어선→운반선→항만 연결의 출발점으로 활용한다.

· S&P Sea-web과 AISLive는 선박·선주·운영사·항만·과거 항적을 연결할 수 있어, 구매 예정인 S&P 데이터를 공급망 그래프의 선박 마스터로 활용하는 것이 적합하다.

2. 가장 중요한 데이터 조합

① 어선 → 운반선

상당 부분 확정

연결 조건

  • GFW encounter 이벤트
  • 두 선박이 일정 거리 이내에서 지속 또는 정지
  • 어선과 냉동운반선의 AIS 동시 존재
  • AIS 단절 직전·재점등 직후 위치
  • 출수 변화
  • 조업 종료 후 운반선과의 반복 접촉
  • 동일 운항사·선주 또는 연관회사

원천

GFW Events API (encounter·loitering) S&P AISLive 항적 S&P Sea-web 소유관계

※ GFW가 조우·체류·환적 가능 이벤트와 항만 방문을 제공하므로 기본 연결 후보를 만들 수 있다.

② 운반선 → 항만

상당 부분 확정

연결 조건

  • AIS 항적과 항만 지오펜스 교차
  • GFW Port Visit
  • S&P 항만 방문 이력
  • UN/LOCODE 항만 코드 정합
  • FAO PSMA 지정항만·검사·입항거부 기록

원천

GFW Events API (port_visit) UN/LOCODE FAO PSMA-GIES S&P AISLive

※ UN/LOCODE를 항만 노드 기준키로 사용한다. PSMA-GIES 상세자료 일부는 기관 계정이 필요하다.

③ 항만 → 중국 수산시장

확률 추정

연결 조건

  • 항만 도착시간과 시장별 품목 가격·물량 급증의 시차 상관
  • 항만–시장 이동거리 및 육상 이동시간
  • 항만 주변 냉동창고·가공업체 위치
  • 기업 거래자료(선적·세관)
  • 동일 항만–시장 패턴 반복성
  • 거리·시차·시장별 품목 연관성을 시장별 연결 후보에 반영

원천

pfsc.agri.cn 공개 API — 시장별·품목별 최신 도매가격·품목 상승·하락 순위·일별 가격지수 data.moa.gov.cn — 수산물 가격지수·주간 가격 동향·월별 가격 보고서 개별 수산시장 주간 시황 (웨이하이·칭다오 등) 중국 농업농촌부 어업경제관리국 (가공업체·냉동창고 통계)

※ 가격 통계만으로 특정 선박의 어획물이 특정 시장으로 이동했다는 직접 거래관계를 알 수 없어 확률 관계로 생성한다. 다만 pfsc.agri.cn 공개 API가 확인되어 시장별·품목별 가격지수와 상승·하락 순위 데이터로 수집 가능하다.

④ 시장·가공업체 → 수입업체

추정

연결 조건

  • HS코드(HS 03류) 기반 품목 연계
  • 국가·지역·월별 수출입 물량 정합
  • 선하증권 기준 수출자–수입자 관계
  • 기업 주소와 항만·시장 간 이동경로

원천

중국 해관총서 통계 플랫폼 (기간·수출입·상품코드 조건 조회) UN Comtrade (HS03 국가 간 물량·금액) S&P Panjiva (선하증권·세관자료 기반 기업 간 관계) 식약처 수산물 수입업체 API (업체명·영업허가번호·주소·대표자)

※ 해관총서 공개 통계와 UN Comtrade는 대부분 집계 데이터라 실제 중국 업체와 한국 수입업체를 직접 연결하기 어렵다. 기업 간 실제 선적 관계는 Panjiva가 가장 적합하다.

3. 구축 우선순위

1단계 즉시 수집 가능한 데이터

  • 해경 내부 AIS·외국어선 허가·선박제원
  • S&P AISLive·Sea-web
  • Global Fishing Watch Vessel·Events API
  • UN/LOCODE
  • FAO Global Record
  • WCPFC·ICCAT·TMT IUU 목록
  • 중국 수산물 도매시장 가격 — pfsc.agri.cn 공개 API (UA·Referer 헤더 필요)
  • 중국 수산물 가격지수·주간 동향 — data.moa.gov.cn
  • 개별 수산시장 주간 시황 (웨이하이·칭다오 등) — 입하량·가격변동·공지
  • 중국 해관총서·UN Comtrade
  • 식약처 수산물 수입업체 API

※ FAO Global Record는 어선뿐 아니라 냉동운반선·보급선 정보를 포함하며, 선명·국적이 바뀌어도 유지되는 UVI를 핵심 식별자로 사용한다.

※ WCPFC IUU 목록은 CSV로 선명·과거 선명·국적·IMO·호출부호·IUU 행위를 제공하며, ICCAT 목록에는 선주·운영사 정보도 포함된다.

2단계 추정 연결 생성

  • 어선–운반선 환적 가능성
  • 운반선–항만 방문
  • 항만–시장 거리와 이동시간
  • 시장별 어종·가격 변화
  • 항만 주변 냉동창고·가공업체
  • 기업 주소와 항만·시장 간 이동경로
  • HS코드 기반 품목 연계

3단계 상용데이터 보강

  • S&P Panjiva — 기업 간 수출입 거래
  • S&P Sea-web — 선주·운영사·관리회사
  • Windward — 다크활동, AIS 조작, 허상 항적, 소유구조 위험
  • 위성 SAR 극광영상 — AIS 미송신 선박 확인

※ Windward는 다크활동·AIS 조작·의심 선박 간 접촉·비정상 항만 행동· 소유구조 위험을 분석하므로 공급망 그래프의 위험도 속성으로 활용할 수 있다.

가공업체 —[EXPORTS]→ 수입업체Panjiva 선하증권 · 해관총서 HS코드

5. 식별키 표준

공급망 그래프에서 가장 중요한 것은 서로 다른 원천의 동일 객체를 합치는 것이다. 위 우선순위에 따라 식별키를 적용해 엔티티를 병합한다.

객체 우선 식별키
선박IMO → UVI → MMSI → 호출부호 → 선명+국적+기간

현 사업 권장 조합

S&P AIS·선박소유정보 + Global Fishing Watch 조우·입항 이벤트 + 중국 도매시장 가격 + 중국 해관 통계 + Panjiva 기업 간 선적자료

공개데이터만으로는 어선→운반선→항만까지는 상당 부분 구성할 수 있으나, 항만→특정 가공업체→특정 수산시장을 확정적으로 연결하기는 어렵다. 이 구간은 Panjiva 같은 선적자료, 중국 기업정보, 냉동창고·시장 위치 및 가격 변화를 결합해 확률 관계로 구성해야 한다. 각 공개 통계가 시장·지역·HS코드 단위로 제공되고, Panjiva가 기업·선적 단위 관계를 제공한다는 점에 근거한 판단이다.
